# Log: isa-schema

Drafted the ISA description format (ADR isa-adr-0001, status proposed — awaiting
Eli's review) and proved it end-to-end.

## What exists now

- `isa/README.md` — format spec: 32-bit word, opcode [4:0], GOSUB overlay caveat
  (mask/match most-specific-first), forms, slice-based fields, modifier grammar
  table, editing + provenance rules.
- `isa/ezh_b/arch.toml` — full register file (R0-R7, GPO, GPD, CFS, CFM, SP, PC,
  GPI, RA), all 16 condition codes with aliases (SPO/UNS, SNE/NZS), bit-slice mux
  configs, provenance source registry (spec_b_06, an14650, fsl_header, bunny_build,
  sv_tb w/ advisory-only note).
- `isa/ezh_b/fields.toml` — shared fields incl. the two known split fields
  (shift5_simm, per_addr20_w) expressed as multi-slice mappings.
- `isa/ezh_b/opcodes/` — three worked examples chosen as hardest cases:
  - mov.toml — multi-form (reg vs imm via bit 18 select), COND/S/N modifiers,
    PC-write branch-scheduling restriction
  - per_write.toml — split 20-bit address field
  - nop.toml — full-word fixed encoding (mask 0xFFFFFFFF)
- `isa/tools/validate.py` — stdlib-only validator + C/Verilog demo emitter.

## Proof

`uv run python isa/tools/validate.py --emit` passes:

- all four forms validate; masks/matches derived (MOV forms share mask 0x0004001f,
  distinguished by bit 18)
- emits working C encode macros and Verilog mask/match + part-select decode from the
  same data (the "verilog, c, etc" requirement)
- self-tests encode E_MOV(R1,R2) -> 0x00008400 and E_PER_WRITE(R3,0x32200) ->
  0x32320005 through the slice model and match bunny_build's encoder formulas
  bit-for-bit.
