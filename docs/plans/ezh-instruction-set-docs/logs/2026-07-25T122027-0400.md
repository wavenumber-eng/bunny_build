# Log: platform-guide

# Note for later: platform-guide scope and method (Eli, 2026-07-25)

Direction captured for when `platform-guide` is picked up. Not actioned yet.

## Intent

A dedicated per-MCU section - application/CPU/MCU-specific - rather than one
flat table. Each supported part gets its own treatment: base address, pin mux
options for the EZH/SmartDMA I/O, IRQ number, INPUTMUX trigger map.

## Why the AN's table is only a starting point

AN14650 Table 2 lists base addresses for six rows: LPC5410x, LPC54114/LPC51U68,
LPC55(S)6x/2x, LPC55(S)3x, IMXRT500, MCXNx4x/MCXN23x. That predates a good chunk
of the current portfolio, and the AN carries base addresses only - no pin mux,
no IRQ numbers, no trigger maps. It cannot be the source of record for this
chapter.

## Method: derive it, don't transcribe it

The MCXN947 worked example (see log `source-ranking-and-chipdata`) proved
`nxp-monkey` supplies everything per part, machine-readably:

- `registers/SMARTDMA0.json` - register block, offsets, field names/widths
- `resource_tables/interrupts.json` - IRQ number (54 on MCXN947)
- `registers/INPUTMUX0.json` - `SMARTDMAARCHB_INMUX[n]`, `INP[6:0]`, with the
  full enumerated trigger table
- `signal_configuration.json` - `SMARTDMA_PIO` pin mux options per pin
- `SYSCON0` / `AHBSC` - clock/reset and bus-priority context

**Recommendation: generate this chapter from fetched JSON rather than hand-write
it.** Same discipline the instruction reference already follows - the data is
already structured, and hand-transcription across dozens of parts is exactly
where errors breed. It also means regeneration picks up new parts for free.

## Determine EZH presence empirically

Eli's recollection is MCXA2xx plus 3xx/4xx and "soon 5xx" - flagged as
uncertain, and worth not guessing. Better: **presence of a SmartDMA/EZH register
file in the fetched tree IS the test.** That converts a remembered list into a
definitive one.

Candidate scope from the local index (MCUXpresso tool version 26.06), grouped by
family root:

| Series | Families in index |
|---|---|
| LPC5xx | 55 |
| MCXA1xx | 18 |
| MCXN5xx | 15 |
| MCXA3xx | 8 |
| MCXN2xx | 6 |
| MCXW7xx | 5 |
| MCXN9xx | 4 |
| MCXA2xx | 4 |
| MIMXRT5xx | 3 |

Note **MCXN5xx (15 families)** was not in Eli's list and may be relevant. No
MCXA4xx/A5xx appears in this index version - either not yet published or named
differently; re-check against a newer tool version before concluding.

## Cost caveat

The MCXN947 fetch was ~134 MB / 463 files. Fetching every part number is
impractical; fetch **one part per family root** (~40 fetches) to establish
presence and per-family data, then expand only where variants actually differ.
The cache persists, so this is a one-off.
