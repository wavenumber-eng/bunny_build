# Log: e-end-api-fixed

Addressed the cookbook review finding that the command/execute/stop pattern now
presented `E__END` as actionable while the public API still had the historical
`E_END`/`E__END` declaration-definition mismatch.

Fix:

- `include/bunny_build__psuedo_instr.h` now declares both `E_END()` and
  `E__END()`.
- `src/bunny_build__psuedo_instr.c` keeps the park sequence in `E__END()` and
  adds `E_END()` as a wrapper, so both spellings emit the same bus-idle park
  block.
- `test/cl_build/main.c` has a guarded link probe for both spellings.
- The assembler guide now tells readers to call `E_END()` from the public header
  and notes that `E__END()` remains accepted for older notes/examples.
- The cookbook keeps the pattern direct and notes the public spelling locally.

This preserves the important detail Eli called out: parking with the helper
halts instruction fetching instead of spinning in a loop and consuming AHB
bandwidth.
