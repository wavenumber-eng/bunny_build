# Log: architecture chapter drafted (docs_src/architecture.md)

First prose chapter written. 19 sections, ~7.6k words, covering everything the
step and the `architecture-chapter` exit criterion call for.

## Authoring conventions established (new; folded into the generator design)

- Prose chapters live in `docs_src/` as Markdown (the design doc left the name
  TBD).
- **Provenance is carried in `+++` TOML front matter, not in the body**, keyed
  by section anchor - same delimiter convention dev-std uses for plans/logs.
  This is stronger than annotating prose: non-public source ids (`spec_b_06`,
  `fsl_header`, `sv_tb`) physically cannot reach rendered output, enforcing
  "synthesize, don't copy" structurally rather than by discipline. Mirrors how
  the ISA db keeps `[[provenance]]` blocks out of rendered fields.
- Hedged claims live in `[[unverified]]` front-matter entries (claim, basis,
  resolve_by) AND as inline blockquotes in the body, so a reader sees the
  hedge and a tool can enumerate them.

## Coverage

Sections: what EZH is / system context / dual bus / pipeline + branching /
**living with a pipeline that runs two ahead** / DFETCH / registers / flags /
ALU+shifter+flip / Boolean detection / pending trap / GPIO / heartbeat /
execution supervisor / stack+RA / breakpoint / emergency / **Arm-EZH
interaction** / open questions.

Per Eli's "cover EVERYTHING" direction, two sections are deliberately
exhaustive:

- **Two-ahead nuances** are collected into their own section listing all seven
  places the lookahead is visible in the programmer's model: PC reads +8;
  PC-write-with-S = scheduled branch; ordinary vs scheduled flush; vectored
  hold flushing two unless accelerated; LV entries being 4 words *because*
  scheduled branch + 2 unflushed = 3; the one-shot instruction after
  E_TIGHT_LOOP; breakpoints in a branch shadow being unreconstructable.
- **All Arm/EZH interrupt mechanisms**: EZH->Arm via (1) E_INT_TRIGGER to the
  EZH NVIC slot, (2) E_INT_TRIGGER interrupt *hijack* bus, (3) EZH2ARM write
  under ARM2EZH[1:0]==0b10, (4) event-out mode. Arm->EZH via ignition, the
  ARM2EZH parameter block, the external flag (CTRL[1] -> EX/NEX), pending-trap
  writes synthesizing bit-slice edges, INPUTMUX-routed triggers, breakpoint
  and emergency controls, plus PC/SP observation. Full EZHB register block
  documented including the 0xC0DE key-on-every-write trap.

## Two source conflicts resolved

1. **SPO/SNE direction.** AN14650 §4.2.5.2.1's summary bullet says the extra
   ALU op is performed *when the top bit is 1*. Its own worked example shows
   the opposite: `SPO == 0 -> shift AND OR`, `SPO == 1 -> shift only`. The
   spec, the example, and the ISA db agree - the flag *cancels* the fused ALU
   stage. Chapter documents the db's semantics and notes the AN bullet reads
   backwards, since that bullet is the one most readers will hit first.
2. **CFS vs CFM roles.** A training-deck speaker note has them inverted (CFM
   = source, CFS = combination). AN14650 §3.2 and the ISA db agree: CFS =
   source select + input status, CFM = event select + OR-enable. Followed AN;
   the deck note is simply wrong and is not repeated.

Also corrected: the flag-setting exclusion list in both spec and AN names
`E_GPO_BYTE_MODIFY`, which is not a real mnemonic - the opcode is
`E_MODIFY_GPO_BYTE`. Chapter uses the real name and notes the discrepancy.

## Derived, not copied

The PC = current + 8 constant is not stated outright in any source. Derived it
from three independent worked examples (the label-table `E_ADD_IMM(Rn,PC,-4)`
idiom, the 16x16 multiply's `E_LDR(R0,PC,7)` reaching the DCD nine words down,
and AN14650's own "PC is two instructions ahead" note on `E_ADD_IMMS(PC,PC,8)`)
- all three agree. Documented with the derivation and flagged for bench.

Same for tight-loop geometry: the end-address register points at the first
instruction *past* the body, and the loop body starts *two* instructions after
E_TIGHT_LOOP. Both re-derived from the AN and spec examples and cross-checked
against each other.
