# Log: platform-discovery-review-fixes

Addressed review findings from the first SDK-header discovery commit.

Parser corrections:

- `FSL_FEATURE_SOC_EZH*_COUNT` macros now parse the numeric value. Zero-count
  EZH macros no longer confirm a part.
- `SDMA_IRQn` matching now compares uppercase-to-uppercase, so an RT-style
  uncommented `SDMA_IRQn = 73` line is still recognized as SmartDMA.

Discovery-contract correction:

- The LPC path now includes a broad metadata sweep across feature headers,
  COMMON headers, `chip.yml` files, and EZH-named paths.
- The current pinned LPC repo still has zero feature-header confirmations, but
  the broad sweep finds three unconfirmed COMMON-header candidates:
  `LPC5534`, `LPC5536`, and `LPC55S36`, each exposing `EZH_ARCH_B0_IRQn = 30`.
- Those candidates stay in `index.json` under `series.LPC.unconfirmed_candidates`
  and are not promoted to confirmed platform rows until a presence/base-address
  source is settled.

Public-output correction:

- The generated platform placeholder now says the guide awaits review and
  enrichment of SDK-header discovery data, rather than saying the data pipeline
  has not been implemented.
- Live design/plan wording now uses `E_END` and `nxp-monkey`.
