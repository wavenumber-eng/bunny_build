# Log: isa-schema — review fixes applied

Independent review of the format artifacts confirmed all encoding claims
bit-for-bit but surfaced one factual bug, three validator gaps, and two schema
decisions. Fixes applied this session:

## Fixed

- **fields.toml `s` desc bug**: claimed "for LDRB-family S means signed access" at
  bit 9. Wrong — the LDRB signed flag is bit 21 (`E_LDRBS = E_LDRB + (1<<21)`,
  bunny_build__instr.h:99); bit 9 is only ever set-flags. Dropped the clause and
  added a staged `sgn` field (flag, instr 21:21) for the LDRB/LDR_REG families.
  README modifier table split into two S-suffix rows (bit 9 vs bit 21).
- **Validator gaps** (all in validate.py, all verified to fire via negative test):
  - form's fixed low bits must agree with `[opcode].value` (typo guard; tolerates
    GOSUB-style forms that fix fewer than 5 low bits)
  - opcode values must be unique across files
  - every field in fields.toml is structurally validated even when unreferenced;
    unreferenced fields print WARN (currently: `per_addr20_r`, `sgn` — both staged)
  - new self-test: `per_addr20_r` vs E_PER_READ's `(addr & 0xffffc) << 12`
- **ADR isa-adr-0001**: drafted two new Decision subsections (status stays
  *proposed* — Eli to accept):
  - *Decode mask vs canonical encoding* — fixed = decode-significant, unclaimed =
    reserved-zero (canonical 0, decode don't-care). On acceptance, nop.toml's
    full-word fixed shrinks to opcode-only.
  - *Mnemonic patterns* — per-form bracket notation (`[X]` optional, `{A|B}`
    alternation bound to modifier values); expansion must reproduce the historical
    ~1500-name list exactly. Answers the open mnemonic-suffix question from the
    previous log.

`uv run python isa/tools/validate.py`: all checks pass (2 expected WARNs).
