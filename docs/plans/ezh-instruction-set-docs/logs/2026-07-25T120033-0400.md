# Log: SystemVerilog model applied to the architecture chapter; units trap fixed

Eli flagged two things: the chapter said "PC = current + 8" without units, and
`ezh_tb_package.sv` is a reference source that had not been used for this
chapter. Both addressed.

## The units problem (real defect, fixed)

"+8" was ambiguous, and ambiguously *in this ISA specifically*, because offset
units are not uniform across instruction families:

- `imm12s` (E_ADD_IMM / E_SUB_IMM family) - raw **byte** immediate. One
  instruction = `4`.
- `offset8s` (E_LDR / E_STR family) - **scaled by access size**. For a word
  access one instruction = `1`.

So `E_ADD_IMM(R4,PC,-4)` and `E_LDR(PC,R4,1)` step the same distance written as
`4` and `1`. Confirmed in `fields.toml` and independently in the model
(`acc_offset = extract_misc0() ? 4*acc_offset : acc_offset`).

Answer: PC reads **executing instruction address + 8 bytes** = two 32-bit words.
Every PC-offset statement in the chapter is now unit-qualified, and the
two-ahead section carries a callout contrasting the two notations. This is the
kind of thing that silently produces off-by-one-word bugs, so it is called out
rather than left implicit.

## sv_tb applied to the architecture layer

Prior passes (instruction-prose, verify-encodings) mined the .sv for the
*instruction* layer; it had not been applied to architecture-level behavior.
Doing so confirmed a great deal and produced one genuinely new fact.

Confirmed, no change needed:

- **PC = exec + 8 bytes.** `ezh_pc_manager` seeds its queue boot/+4/+8, ticks
  by +4, executes `pc[$-2]`, and a PC register read returns `pc[$]`.
- **Two-flush vs no-flush.** `schedule_branch` reassigns `pc[$]` and sets no
  cancel bits; `absolute_branch` sets cancel on `pc[$-1]` and `pc[$-2]`. Exactly
  the model the chapter describes.
- **Tight loop geometry.** `tight_loop_start = get_current_pc()` = the
  E_TIGHT_LOOP address + 8, i.e. the body starts two instructions later and the
  instruction between is the one-shot. End address triggers the swap; count
  decrements per swap, giving 1 + count executions.
- **Breakpoint = fetch-address substitution** (`if (pc[$] == breakpoint_addr)
  pc[$] = breakpoint_vector`).
- **Vectored hold**: `table_base = (reg & ~3) + 4` (confirms hold.toml's "+4"),
  LV stride 16 bytes vs 4, acceleration bit `24 + vector`, accelerated ->
  `schedule_branch` (unflushed) else `absolute_branch`. hold.toml already had
  all of this.

New, folded into the chapter:

- **RA capture is branch-kind dependent.** GOTO writes RA only with bit 10 set:
  `PC-4` for an ordinary branch, `PC+4` for a scheduled one - the return address
  skips the two delay slots, otherwise they would re-execute on return. Added as
  an eighth entry in the "living with a pipeline that runs two ahead" section
  and expanded in stack-ra. This is the spec's "return with offset" feature made
  concrete.

New, NOT yet folded in (ordering detail, belongs with breakpoint):

- **Tight-loop swap is evaluated before breakpoint substitution**, with an
  explicit comment that a tight-loop swap means the breakpoint need not trigger.
  Worth a sentence in the breakpoint section; deferred pending Eli's read.

## Cross-check that closed a loop

goto.toml already recorded the immediate-branch formula
`(PC & 0xff800000) | (imm << 2)` and the RA semantics as "ordinary -> GOTO+4,
scheduled -> GOTO+12" (defect candidate #5, tentatively resolved). The model
states the same RA rule as PC-4 / PC+4. **The two notations reconcile only if
PC = GOTO + 8.** So the db's existing adjudication already depended on the
constant this chapter derived - a third independent confirmation, from a
direction that was not consulted when deriving it.

Consequently the pc-read hedge is downgraded in wording from "investigate" to
"confirm": three prose derivations, an executable model, and an existing db
adjudication all agree. It stays on the bench list because none of these is
silicon.
