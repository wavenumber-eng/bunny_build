# Log: instruction-prose — full per-instruction pass from both sources

New step added per Eli: meticulously extract every instruction's prose
(purpose, use, modes, restrictions, intent) from AN14650 §5 AND the original
Arch B spec, and synthesize accurate semantics prose into the db. Pass one is
complete over all 25 opcode files; Eli reviews next, then re-inspects the
rendered HTML.

Also per Eli (mid-session): no personal names in any documentation — scrubbed
"the EZH creator" phrasing throughout isa/, tools, plan, and logs; generated
docs may cite the public cookbook (kept) but nothing else.

## Method

- AN14650 §5 (all 29 sections, pages 29-50) extracted and read in full —
  descriptions, supported-options lists, format tables, restrictions, and
  performance text per instruction.
- Arch B spec instruction chapter (plus the architecture prose before it:
  flag-setting rules, SPO/SNE legality, DFETCH stall model, boolean detector
  and vectored-hold sections) extracted from the .docx in place and read in
  full. Synthesized only — no spec text copied; provenance records section
  pointers.
- Every [semantics] prose block rewritten for intent + operation + modes;
  restrictions rebuilt as the union of both sources plus the cross-cutting
  spec rules (which opcodes can never set flags; SPO/SNE unpredictable-use
  list). Curated correction records (andor, modify_gpo_byte) kept verbatim;
  adjudication items preserved. spec_b_06 provenance entries added to every
  file; an14650 details now carry exact section numbers.

## Errors this pass caught in OUR OWN db prose

- **ALU post-stage side**: db said the shift/flip applies to the second
  operand *before* the operation; both sources say it is a post-shift/flip
  of the *result* (mnemonic order ADD-N-F-LSL-S spells it). All 7 ALU files
  and the f_alu field description corrected.
- **Peripheral window size**: db said "1MB window"; sources say a 20-bit
  word offset = 22-bit / 4MB byte region above 0x4000_0000. per_read,
  per_write, and both per_addr20 field descriptions corrected.
- Numerous omissions now filled: LDR/STR pointer-hazard + CFS restrictions,
  DFETCH latency prose, TIGHT_LOOP loop-start and count+1 semantics, HOLD
  detector/priority/acceleration detail with the CFS/CFM-outstanding-read
  stall and the BS-condition caveat, GOTO RA-backup rules, GOSUB RA-always-
  overwritten, PUSH/POP upward-growing stack, INT_TRIGGER common-output
  behavior.

## Source-document defects noticed (recorded in provenance/prose)

- AN14650 §5.12 (R-shift family) description sentence says "byte or bit
  order flipping" — a copy-paste from §5.11; its own options list and both
  other sources agree the family shifts by a register's low byte.
- AN14650 §5.20 says the heartbeat "must be initialized using the
  E_WAIT_FOR_BEAT instruction" — its own example shows E_HEART_RYTHM_IMM;
  obvious typo, db prose states the correct init flow.
