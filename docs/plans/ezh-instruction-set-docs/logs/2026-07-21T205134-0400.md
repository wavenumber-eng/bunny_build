## New tooling (isa/tools/)

- `extract_fsl.py` — parses every `#define E_*` in
  `C:\eli\ezh\doc_project\fsl_ezh_armclang.h` (read in place; nothing
  confidential copied) and numerically probes it like extract_header.py.
  Handles all four body shapes: function-like `%c0`, object-like `%c0`
  (E_NOP), stringized gas-expression (E_GOTO family — reassembled with gas
  precedence, where `<<` binds tighter than `+`, opposite of C), and
  known-defective macros repaired-as-intended via an explicit DEFECTS table.
  Reconciliation: 1502 macros + 3 directive wrappers (E_DCD/E_DCD_VAL/E_LABEL)
  = all 1505 `#define E_` lines classified; anything else is a loud ERROR.
- `verify_fsl.py` — (1) diffs arch.toml register/condition/bit-slice constants
  against the header's own #defines (aliases included); (2) structurally
  matches every macro to exactly one db form/alias, name-free, reusing the
  verify_encodings.py matcher; (3) cross-diffs base words + positional
  argument bit-maps for all 1492 names shared with bunny_build__instr.h;
  (4) coverage: dead forms, modifiers never observed set, operands never
  exercised are all failures; (5) prints the adjudication report.
- Refactor: extract_header.py gained `extract()` (errors as data, not prints);
  verify_encodings.py's try_form/try_alias hoisted to module level and shared.

## New findings for the EZH creator — fsl header macros that cannot compile (9 total)

- **E_ANDOR / E_ANDORS / E_COND_ANDOR / E_COND_ANDORS** (lines 1978-1981):
  missing `+` between `(rsrc<<14)` and `(rand<<20)` — expands to
  `(int)(int)`, a compile error. The ANDOR family was flagged "DOUBLE CHECK"
  by the EZH creator and these macros can never have been used as written. Intended
  encoding (with `+`) verifies against andor.toml.
- **E_MODIFY_GPO_BYTE** (line 3327): parameters `ormask,xormask` but body
  says `ordmask`/`xordmask` — undeclared identifiers, compile error.
  Intended encoding verifies against modify_gpo_byte.toml.
- **All four COND_*_NRA hold variants** (E_COND_VECTORED_HOLD_NRA,
  E_COND_VECTORED_HOLD_LV_NRA, E_COND_ACC_VECTORED_HOLD_NRA,
  E_COND_ACC_VECTORED_HOLD_LV_NRA): the known space-before-parameter-list
  defect is a copy-paste lineage, not a one-off. Intended encodings verify.

Name sets are otherwise identical: bunny_build reproduces every fsl mnemonic
except the 10 known non-inline ones (E_NOP, E_GOSUB, 8-name E_GOTO family),
which verify_encodings.py checks by direct formula.
