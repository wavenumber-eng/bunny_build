# Naming convention: SmartDMA is the official NXP name (Eli, 2026-07-25)

General note with doc-set-wide consequences, so recorded as a convention rather
than fixed in one place.

## The point

NXP calls this block **SmartDMA** in official documentation. It is also the name
in the silicon, which the MCXN947 chip data made concrete:

- peripheral `SMARTDMA0`
- trigger mux `SMARTDMAARCHB_INMUX[n]`
- interrupt `SMARTDMA_IRQn` / `SMARTDMA_IRQHandler`
- pin function `SMARTDMA_PIO`

**EZH** ("EZ Handler") is the original architecture name. It survives in exactly
the places a programmer touches: the `E_*` mnemonics, the `fsl_ezh_*` headers,
the `EZHB_*` control registers - and in this project's own naming (`isa/ezh_b`,
the plan id).

## Why it matters beyond wording

Discoverability. A reader looking for this hardware will search "SmartDMA",
because that is the only name on the Reference Manual, the SDK, and the config
tools. An EZH-only doc set is invisible to them. This is the common case, not an
edge case.

## Convention adopted

Use **EZH** for architecture and instruction-set material; use **SmartDMA** for
part-specific material, because that is what an RM, SDK header, or config tool
will call it. Both names must resolve to the same content everywhere.

Recorded in three places so it survives this session:

1. `arch.toml [glossary.naming]` - the canonical statement, alongside the other
   architecture glossary entries the generator already renders.
2. Architecture chapter - a callout immediately under the opening paragraph
   establishing the equivalence and listing the silicon-side names, so a reader
   who arrived by either route is oriented in the first screen. Replaces a
   weaker parenthetical that framed SmartDMA as merely a newer-parts rebrand,
   which undersold it - AN14650 is titled "SmartDMA Cookbook" and covers LPC5500
   too.
3. Generator design doc - added **EZH / SmartDMA synonymy** as a required search
   tier, above the mnemonic lookup, with the note that a search for one name
   returning nothing is a discoverability failure. Extends to the
   `SMARTDMA0` / `EZHB_*` register spellings.

## Consequence for platform-guide

Reinforces the note in `platform-guide-scope-note`: that chapter is part-specific
material and should use SmartDMA naming throughout, matching the RM and the
generated data it will be built from. The peripheral will literally be named
`SMARTDMA0` in its source JSON.
