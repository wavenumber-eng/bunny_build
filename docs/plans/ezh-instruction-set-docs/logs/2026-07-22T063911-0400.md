# Log: instruction-prose — iteration two (review fixes)

External review verified the pass (ALU post-stage correction confirmed
against executable SV semantics; both AN14650 defect reports verbatim-
accurate; HOLD/LDR/TIGHT_LOOP/GOTO/GOSUB deep claims all trace) but caught
one regression and several gaps. All addressed:

## MAJOR (reverted): the peripheral window is 1MB, not 4MB

Pass one "corrected" 1MB to 4MB on the strength of AN14650 §5.28's note
("20-bit immediate offset… covers a 22-bit offset region") — but that note
is arithmetically impossible against the encoding, and three witnesses
prove 1MB: the encoded field is 18 bits (PER_READ instr[31:14]; PER_WRITE
[31:24]+[19:10]), the SV computes 0x40000000 + (inst[31:14] << 2) (max
+0xFFFFC), and real camera code passes byte offsets. Reverted in
fields.toml (both descs), both opcode proses, and both an14650 provenance
details; §5.28's note recorded as **AN14650 defect #3**. isa/README.md's
1MB statement was correct all along. Also removed the "data lands via
DFETCH" read-machinery sentence from per_write (source only equates
performance with E_LDR).

## Moderate

- gosub.toml decode-order sentence was self-contradictory ("match before
  any other opcode … smallest mask"): rewritten to the actual safety
  property — no other defined opcode value has bits [1:0] = 0b11, so no
  other pattern can match such a word; GOSUB falling out LAST under
  most-specific-first is natural and correct.
- arch.toml: GPI is also the discard destination when a result should not
  be stored (the CMP/TST idiom: S-variant op with dest = GPI) — was
  documented "read only". CFS/CFM descriptions enriched to the spec's
  actual layout (CFS: 8x3-bit slice source selects + 8 slice-input bits;
  CFM: 8x3-bit slice mux selects + 8 enable-OR bits).

## Minor

- bitop.toml: BTST explicitly writes its destination (dest = Rdata AND
  (1 << bit)) — unlike ARM's TST; GPI is the discard destination.
- rshift.toml: shift amounts >= 32 are spec-silent; sv_tb (advisory,
  verified at its shift_by_32_or_more logic) applies rotate modulo 32 and
  saturates shifts (carry = last bit at exactly 32, cleared beyond). Noted
  in prose + restriction, sv_tb provenance added, on the adjudication list.

## Adjudication list additions

- rshift >= 32 shift-amount behavior (above).
- Belt-and-braces: is the peripheral-address hardware register 20 bits with
  only 18 wired to the encoders? (SV agreeing with both headers makes this
  unlikely; recorded for completeness.)
