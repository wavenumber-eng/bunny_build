# Correction: DMA-descriptor note had a contaminated attribution

The reviewer flagged that a DMA-descriptor note appeared in
`review-round2-fixed` attributed to them, having made no such note. Checked, and
the answer is split.

## What the log actually said

It was headed "Note for the cookbook (Eli, in passing)" - attributed to Eli, not
to the reviewer. Eli did say it, verbatim, opening the message that forwarded
the review:

> I think dma descriptors and such are setup new ever time.

So the specific claim - that it was attributed to the reviewer - is not correct.
The misread is understandable: the note sat at the tail of a log otherwise
entirely composed of review findings, with no marker separating it.

## But the flag was right, and the defect is mine

Two things were wrong with that note, and both are the kind this project
explicitly exists to avoid:

1. **I dropped the hedge.** Eli wrote "I think"; I quoted it as a flat assertion,
   "DMA descriptors and such are set up new every time".
2. **I merged my own inference into someone else's attribution.** Everything
   after the quote - the boot-with-parameters framing, `EZHB_ARM2EZH` carrying a
   fresh parameter-block pointer per run, the argument about why EZH suits
   variable-shape work that descriptor DMA handles badly - was mine. None of it
   was Eli's claim, and none of it is verified. Presented inside a note headed
   with his name, it reads as his.

That is a provenance failure of exactly the type the source-ranking work this
session was meant to protect against, committed in the plan record itself.

## Fixed

The section in `2026-07-25T182822-0400.md` is amended in place, with a visible
amendment marker pointing at this log. It now: quotes Eli verbatim including the
hedge; states plainly that it is his aside and not a review finding; separates
my elaboration and marks it as my inference and unverified; records that the
inference is plausible (the reference boot sequence does set
`EZHB_ARM2EZH = pPara | mask` before each ignition, and programs re-read it from
the top) but that what Eli meant by "DMA descriptors" is unresolved - possibly
NXP's SmartDMA driver descriptors, possibly DMA descriptors generally.

Status recorded as: unverified aside, ownership split, resolve the intent before
`pattern-library` uses it as a framing.

## Practice note

Amending a timestamped log in place is not ideal. The alternative - leaving a
known-contaminated attribution in the record and correcting it only in a later
entry - is worse, because the wrong text is what a future reader encounters
first. Amendment plus a visible marker plus this log keeps the change auditable.

The general rule this should have followed: when a passing remark gets promoted
into the plan record, quote it exactly, keep its hedges, and put any elaboration
under a separate heading with its own attribution. A remark is not a finding.
