# Log: platform-sdk-header-discovery

Started the `platform-guide` implementation with the cheap, reproducible SDK
header stages from `docs/design/platform-data-pipeline.html`.

Added `isa/tools/discover_parts.py`:

- follows the pinned `mcuxsdk-manifests` revision
  `d00fe90aef626b082bbd0a5358620625c9297afb`;
- reads `submanifests/devices/{MCX,LPC,RT}.yml` to get exact device-repo
  revisions;
- uses the unauthenticated GitHub tree API plus raw header fetches, not
  GitHub code search, because code search requires authentication;
- scans feature headers for `FSL_FEATURE_SOC_SMARTDMA_COUNT` or `EZH_ARCH_B`;
- extracts IRQs from `IRQn_Type` in `*_COMMON.h`;
- extracts SmartDMA-prefixed base-address macros where the SDK exposes them;
- writes deterministic JSON to `isa/ezh_b/platform/`, with one part file per
  SDK-confirmed part;
- supports `--check` for stale-output failure and `--require-complete` for
  hard audit failure on unresolved extraction gaps.

First committed generation result:

- 57 SDK-confirmed parts;
- 77 core views;
- MCX: 54 parts, 73 core views;
- RT: 3 parts, 4 core views;
- LPC: 0 SDK-confirmed parts from the current pinned LPC repo.

Open extraction gaps are intentionally explicit:

- `--require-complete` fails because the pinned LPC repo has no feature header
  matching `FSL_FEATURE_SOC_SMARTDMA_COUNT` or `EZH_ARCH_B`; legacy LPC rows
  need AN/RM/nxp-monkey confirmation.
- `--require-complete` also fails for RT500 base addresses: `MIMXRT533S`,
  `MIMXRT555S`, and both `MIMXRT595S` core views advertise SmartDMA and expose
  `SDMA_IRQn`, but the SDK COMMON headers do not provide a SmartDMA-prefixed
  base-address macro.

This does not complete the platform guide. It establishes the deterministic
stage 1/2 data source and makes the remaining source gaps machine-visible.
