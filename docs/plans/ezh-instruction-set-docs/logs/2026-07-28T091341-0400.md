# Log: design-doc-intent-audit

Audited the design docs, ADRs, active plan, ISA README, and archived generator
spike against the landed `isa/tools/gen_docs.py` implementation.

Findings and updates:

- `docs/design/isa-doc-generator.html` already matched the one-page instruction
  reference, static MiniSearch search index, chapter linter, public-output scan,
  and deterministic `--check` path. Updated it to document the `.ezh-docs-generated`
  output sentinel and the current compact reference UI instead of the old amber
  prototype style.
- `docs/isa/adr/isa-adr-0001-*.md` and `isa-adr-0002-*.md` still used review
  wording from the early cleanup phase. Rewrote those clauses as source, bench,
  owner, or private review without changing the technical decisions.
- `isa/README.md` still allowed rendered `sv_tb`-sourced wording that the public
  scanner now rejects. Rewrote the edit rule so internal-analysis facts render
  without private-source attribution unless a public source supports them.
- The active plan's human-facing hardware-review wording now says open hardware
  questions and bench confirmation. The pending step id was renamed from the old
  label to `hardware-bench-confirmation`, and the external-review dependency was
  updated with it.
- `isa/tools/gen_docs_spike.py` is now explicitly described as an archived
  prototype; its style block is historical and not the current site contract.
- Helper-tool prose/output in `verify_fsl.py`, `extract_fsl.py`,
  `expand_mnemonics.py`, and `pc_model.py` now uses review terminology.
- Follow-up review also cleaned non-renderable ISA metadata/source notes in
  `arch.toml`, `andor.toml`, `ldr.toml`, and `modify_gpo_byte.toml`. The old
  review-process terms remain only in the linter/public-scan marker tables,
  where they are the strings that must fail if they reach renderable text.

No generator behavior change was needed for this audit.
