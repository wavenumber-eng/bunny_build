# Log: populate-isa-db — external review findings and fixes

Independent review of the population session confirmed the tooling and all five
"notable discoveries," but caught a real hole: **the "all encoder functions
verified" claim was false**. The extractor's regex required the function body to
be exactly one `add_instruction(...)` call and silently dropped non-matching
bodies. The header has 1492 real inline encoders; only 1487 were probed.

## What was missing (now fixed)

- **E_ANDOR family — opcode 0x16** (4 fns): bodies carry a pass-1 runtime
  warning `DOUBLE CHECK E_ANDOR ENCODING`, which broke the regex. These are the
  single highest-priority adjudication items for the EZH creator (the author himself flagged them) and the pipeline had silently skipped them. Now `andor.toml`,
  with the warning recorded in restrictions/provenance.
- **E_MODIFY_GPO_BYTE — opcode 0x1e** (1 fn): same warning preamble, same
  silent drop. Now `modify_gpo_byte.toml` (AND/OR/XOR mask bytes in
  [15:8]/[23:16]/[31:24]; no cond possible).
- **E_GOTO family — opcode 0x15**: non-inline (two-pass label resolution in
  `src/bunny_build__instr.c`), so outside the probe universe; NOP and GOSUB had
  direct checks but GOTO was forgotten. Now `goto.toml`: bit 9 = imm/reg form
  select, bit 10 = link, imm target = addr[20:2] -> instr[29:11] (word
  alignment makes `(addr & 0x1FFFFF) << 9` safe past the two flags), register
  target in src1. Verifier gained four direct formula checks.

## Systemic fixes

- `extract_header.py`: regex now accepts the warning-printf preamble, and a
  reconciliation pass diffs every `static inline void E_*(` declaration against
  the matched set — any body shape the extractor doesn't understand is a loud
  ERROR, never a silent drop.
- Stale ADR parenthetical about NOP's mask corrected.

## Result

`validate.py` and `verify_encodings.py` both pass: **25 opcode files** (exactly
the ADR's original ~25 estimate), 42 forms + 7 aliases, **1492/1492** header
encoders matched (andor/default 4, modify_gpo_byte/default 1, goto via direct
checks).

## Carried forward to verify-encodings (from review)

- Verifier blind spots to close during the fsl-header diff: a DB modifier bit
  never set by any header fn passes silently (phantom modifiers); operands
  never exercised by any fn argument aren't validated. Per-operand coverage
  counting would close both.
- Mnemonic `binds` data is still untested by any tool — treat as draft until
  pattern expansion is checked against the full historical name list.
