# Log: review follow-up — GOTO window semantics, alias rendering

External review of the timing pass + ADR-0002 slice approved both and
surfaced three findings; all addressed.

## 1. GOTO 2MB window — NEW adjudication item for the EZH creator (substantive)

AN14650 §5.22: the 21-bit immediate branch keeps the **top 9 address bits of
PC at execution time** — a branch within the current 2MB *window*. The db
previously said "limited to the low 2MB (21-bit absolute address)", matching
bunny_build's `& 0x1FFFFF` absolute-address treatment. The two agree only
while code executes below 0x200000 (true for SmartDMA RAM today, but an
assumption, not a property). goto.toml reworded to window semantics with the
bunny_build assumption called out; provenance entries sharpened. This bears
on assembler correctness, not just docs — added to the adjudication list
alongside the ANDOR width, hold table replica, and rshift R0-R7 items.

## 2. Alias mnemonics now render (spike)

`render_opcode` gained an ALIASES panel (name, base word, preset expansion —
same match-word + preset-encode math the 1502/1502 expansion check uses),
alias names count into the index, and the generator prints the rendered
total: **1502 mnemonics rendered**, matching the expand_mnemonics guarantee.
The real generator inherits this and should keep asserting the total.

## 3. Recorded for the real generator

Design doc deferred-list gains the per-form machine-readable timing note
(docs match AN14650's per-opcode granularity; the simulator will want
per-form cycles). The full mnemonic-to-page index table remains an ADR-0002
commitment for build-static-html.

All four verifiers green; preview artifact republished (same URL).
