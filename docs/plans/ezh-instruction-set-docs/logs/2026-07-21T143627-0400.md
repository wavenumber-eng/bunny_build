# Log: inventory-sources

First working session on the curated source set (`C:\eli\ezh\doc_project\`, hand-picked 2026-07-21). Old code sample projects are explicitly out of focus per Eli.

## Findings

**Opcode map recovered.** `ezh_tb_package.sv` opens with the full 5-bit opcode table:
0x00 MOV, 0x01 AHB_READ, 0x02 AHB_WRITE, 0x04 PER_READ, 0x05 PER_WRITE, 0x06 ADD,
0x08 SUB, 0x09 ADC, 0x0A SBC, 0x0C OR, 0x0D AND, 0x0E XOR, 0x10 SHIFT, 0x11 FLIP,
0x12 NOP, 0x14 INT_TRIGGER, 0x15 GOTO, 0x16 ANDOR, 0x18 BIT_MANIPULATE,
0x19 SHIFT_BY_BYTE, 0x1A TIGHT_LOOP, 0x1C BOOLEAN_DETECT, 0x1D REG_OFFSET_ACCESS,
0x1E MODIFY_GPO_BYTE, plus GOSUB encoded as `xxx11` (any opcode with low bits 11).
The package also models PC management: 3-stage pipeline (3 PC queue entries), scheduled
branches, tight-loop hardware, breakpoint + emergency vectors.

**Mnemonic surface compared.** Extracted every `E_*` mnemonic from the original Keil
header (`fsl_ezh_armclang.h`, 3337 lines, author the EZH creator) and from
`include/bunny_build__instr.h` (3224 lines):

- Original header: 1498 function-like + 3 object-like (E_NOP, E_HOLD, E_WAIT_FOR_BEAT)
- bunny_build: 1502
- **bunny_build covers the original 1:1.** Only deltas: original-only E_DCD / E_DCD_VAL /
  E_LABEL (assembler directives — bunny_build replaces these with its label API), and
  bunny_build-only E_COND_*_HOLD_*_NRA variants that the original *intended* to have but
  botched: `#define E_COND_VECTORED_HOLD_NRA (cond,table)` has a space before the
  parameter list, making it a broken object-like macro. Latent bug in the original
  tooling, fixed in bunny_build. Worth a note in the docs.

**~1500 mnemonics are really ~25 base opcodes x a modifier matrix**: COND (conditional
execution), S (set flags), N (invert result), IMM, and barrel-shifter fusion variants
(LSL/LSR/ASR/ROR as prefix or suffix, F/FEND/FBIT flips, R-register-shift-amount).
The new instruction set reference should document base opcodes + orthogonal modifier
grammar, not 1500 flat entries. The spec confirms: "opcodes are constructed in the same
order as they are executed in the pipeline" (e.g. E_SUBN_LSLS = sub, negate, LSL, set flags).

**Spec text extracted.** Wrote regex-based OOXML extractors (scratchpad
`extract_office.py`); pulled plain text from both .docx and both .pptx. The Arch B spec
S5 "Instruction Set" (30 pages) has per-instruction Purpose / Supported options /
Format / Restrictions. Caveat: the bit-level format tables are color-coded Word tables;
color semantics (orange = optional field) are lost in text extraction — bit positions
must come from the macro headers / bunny_build source, with the spec supplying semantics
and restrictions. Spec S4 covers architecture: dual bus, pipeline/branching, registers,
conditional flags, boolean detection, vectored holds, barrel shifter, stack, GPIO,
heartbeat timer, supervisor, breakpoint, emergency mode. Also documents the acronym
glossary for the mnemonic grammar.

**Provenance caution.** `fsl_ezh_armclang.h` carries an NXP confidential/proprietary
banner. It informs the new docs; nothing is copied verbatim.
