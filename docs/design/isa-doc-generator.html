Design: ISA documentation generator

Status: design accepted (ADR isa-adr-0002); implementation lands in the build-static-html plan step. Decision record: docs/isa/adr/isa-adr-0002-custom-static-html-doc-generator-driven-by-the-isa-database.md. Working spike: isa/tools/gen_docs_spike.py (stdlib-only; superseded by the generator described here).

Purpose and scope

Render the machine-readable ISA database (isa/, ADR isa-adr-0001) plus narrative Markdown chapters into the static HTML documentation set that ships in this repository. The generator is ISA-db consumer #1: everything bit-accurate on a page (encodings, field layouts, modifier matrices, mnemonic lists, timing) comes from the database, which is itself mechanically verified against the original fsl header and the bunny_build encoders. Nothing bit-accurate is ever hand-written in a page.

Inputs and outputs

InputRole
isa/ezh_b/arch.toml, fields.toml, opcodes/*.tomlAll reference content: forms, fixed bits, operand/modifier fields, mnemonic patterns, timing, restrictions, provenance.
docs_src/*.md (name TBD at implementation) Prose chapters: architecture overview, programming pattern library.
docs_src/templates/*.html.j2Jinja2 page templates.
docs_src/style.cssSingle stylesheet, inlined into every page at build time (self-contained output).

Output: docs/html/ — an index page, one page per base opcode, and one page per prose chapter. Fully self-contained: no CDN fonts, scripts, or images; diagrams are inline SVG. Output is deterministic (stable ordering, no timestamps) and committed to the repository.

Regeneration and drift check

uv run python isa/tools/gen_docs.py          # regenerate docs/html/
uv run python isa/tools/gen_docs.py --check  # fail if committed output is stale

--check regenerates to a temporary directory and diffs against the committed tree; any difference is a failure. It joins the existing verifier suite (validate.py, verify_encodings.py, verify_fsl.py, expand_mnemonics.py) so documentation drift fails CI exactly the way encoding drift does. Generated output is only ever committed together with a passing check.

Architecture

isa/*.toml ──▶ data layer ──▶ page model ──▶ Jinja2 templates ──▶ docs/html/
               (validate.load + derivations)         ▲
docs_src/*.md ──▶ markdown + cross-link resolution ──┘
  • Data layer — reuses the verifier modules rather than reimplementing them: validate.load() for parsing, verify_encodings.form_mask_match() for decode mask/match, expand_mnemonics.expand() for the name lists (the same code whose output is verified 1502/1502 against the fsl header). Derives the bitfield segment model per form: per-bit ownership (fixed / field / reserved-zero), merged into contiguous same-owner runs.
  • Page model — plain dicts handed to templates; no logic in templates beyond iteration and formatting.
  • Templates — Jinja2 (jinja2 dev dependency), one template per page kind plus a shared layout.
  • Prose chapters — Markdown rendered with python-markdown; [[E_NAME]] tokens resolve against the expanded mnemonic set to opcode-page links, unresolved names are build errors.

Opcode page structure

  1. Opcode name, 5-bit value, family.
  2. Semantics prose and restrictions (from the db, synthesized text only).
  3. Timing: cycles plus qualifying note.
  4. Per form: syntax line; derived decode mask/match; bitfield diagram; form notes; expanded mnemonic table (name, canonical base word) — including alias mnemonics (E_POP/E_PUSH families) on their base form's page, presented as presets of that form.
  5. Public-source citations only (see Provenance).

Bitfield diagrams

Inline SVG generated from the slice data — the third emitter alongside the C and Verilog demos in validate.py. Algorithm (proved in the spike): classify each of the 32 bits as fixed (with its bit value), owned by an operand/modifier field, or reserved-zero; merge adjacent same-owner bits into segments; render one labeled cell per segment with bit indices at the segment boundaries. Fixed segments show their binary value; reserved-zero segments show 0; split fields (e.g. the PER_WRITE address) naturally render as multiple cells carrying the same field name.

Provenance rendering

Source ids come from arch.toml [sources], each flagged public. Only public sources (AN14650, bunny_build) render as citations, with section numbers where recorded. Non-public ids (spec_b_06, fsl_header, sv_tb) never appear in generated output; the prose they informed is synthesized text in the db. This enforces the plan's "synthesize, don't copy" rule at the rendering layer as well as the authoring layer.

Styling

Single hand-written stylesheet, inlined at build time. Token-based custom properties with light and dark themes (prefers-color-scheme plus data-theme override); SVG diagram cells styled through CSS classes so diagrams follow the theme. Encoding columns use tabular numerals; wide tables scroll inside their own container.

Open: visual direction (palette, typography, identity) is pending direction from Eli. The spike's steel-blue placeholder styling stands in until then; the token layer is the seam where the real direction drops in.
